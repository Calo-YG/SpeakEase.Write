## 阶段一：边缘业务（P1）

这些是核心创作流的支撑设施，有真实的业务逻辑和逆向流程。

### 1.1 创作会话管理

- **领域实体**：新建 `AICreationSessionEntity`
- **描述**：管理一次 AI 协作会话的生命周期
- **核心字段**：
  - `SessionId`, `WorkId`, `UserId`
  - `Status`（active / paused / closed / expired）
  - `StartedAt`, `LastActivityAt`, `ExpiresAt`
  - `TurnCount`（当前轮次）
  - `ContextSnapshot`（最后一轮的黑板上下文快照，JSON）
  - `AdoptedContent`（已采纳的内容列表，JSON）
- **业务规则**：

  ```
  正向：
    开始会话 → 设置活跃状态 → 关联当前黑板
    多轮对话 → TurnCount++ → 更新黑板快照
    采纳内容 → 追加到 AdoptedContent → 不清除历史未采纳内容
    关闭会话 → 状态改为 closed → 释放活跃锁
  
  逆向：
    取消会话 → 丢弃所有未采纳内容 → 状态改为 cancelled
    回滚到上一步 → 恢复上一步的黑板快照 → 清除该轮之后的对话
    恢复已关闭会话 → 状态改回 active → 恢复上下文
    超时过期 → 自动改为 expired → 用户可手动恢复
  
  约束：
    - 同一作品同时只能有一个活跃会话
    - 超过 10 轮→ 自动压缩早期上下文摘要
    - 超过 24 小时未活动 → 自动过期
    - 会话关闭前提示用户是否有未采纳内容
  ```

- **依赖**：0.2
- **预估**：2 天

### 1.2 版本草稿管理

- **领域实体**：已有 `ChapterVersionEntity`
- **描述**：AI 生成的内容在用户确认前，以草稿版本形式管理，而不是直接覆盖正文
- **业务逻辑**：

  ```
  正向：
    Agent 生成完成 → 自动创建草稿版本（Source = "ai-generate"）
    用户手动保存 → 创建手动版本（Source = "manual"）
    自动保存 → 创建自动版本（Source = "autosave"）
    
  逆向：
    用户选择"恢复上一版" → 从版本历史中恢复内容
    用户选择"仅采纳此段" → 选择性合并到当前版本
    清理旧版本 → 保留最近 N 个版本，清理中间版本
    
  规则：
    - 每个章节保留最近 20 个版本
    - AI 生成版本标记 modelId 便于溯源
    - 手动版本永远不自动删除
  ```

- **依赖**：实体已存在，无依赖
- **预估**：1 天

### 1.3 上下文快照与黑板恢复

- **领域实体**：已有 `MemorySnapshotEntity`
- **描述**：每次 Agent 调用前后，自动对黑板做快照。当用户"重新开始"或"回退"时，从快照恢复黑板状态
- **业务逻辑**：

  ```
  正向：
    Agent 执行前 → 保存 BeforeSnapshot
    Agent 执行后 → 保存 AfterSnapshot
    用户采纳 → AfterSnapshot 标记为"已确认"
    
  逆向：
    用户回退到某一步 → 找到对应的 BeforeSnapshot → 重建黑板
    用户"恢复现场" → 找到最后一次 AfterSnapshot → 重建黑板
    
  规则：
    - 快照不存全量内容，只存增量（diff）
    - 超过 7 天的快全量自动归档到文件存储
  ```

- **依赖**：1.1（会话绑定快照生命周期）
- **预估**：2 天

## 阶段二：核心创作流（P1-P2） ✅ 已完成

这些是用户直接感知的核心功能。

### 2.1 AI 写作闭环（Agent → 编辑器 → 用户确认 → 落库）✅

- **描述**：把多 Agent 系统接入完整的用户交互流程
- **完整链路**：

  ```
  用户在编辑器打开 AI 面板
    → 输入需求 ("帮我写第三章")
    → CreationOrchestrator 执行
      → Router 判定路由
      → 构建黑板
      → 执行目标 Agent（流式输出）
      → 前端实时渲染内容到编辑器
    → 用户看到内容边生成边展示
    → 用户操作：
      ├── 「采纳」→ 内容填入编辑器，创建草稿版本
      ├── 「修改并采纳」→ 用户手动修改后再保存
      ├── 「再写一次」→ 重新触发 Agent（带之前不满意的上下文）
      ├── 「部分采纳」→ 只保留某一段落
      └── 「放弃」→ 清空预览，无事发生
  ```

- **技术要点**：
  - 黑板增量更新（不是全量重建）
  - AgentStreamChunk 的 ContentType 辨析
  - 用户确认后只调 `UpdateChapterAsync`，不用 Function Calling
- **依赖**：0.2, 1.1, 1.2
- **预估**：3 天

### 2.2 逆流程：内容回退与版本回溯 ✅

- **描述**：用户对当前内容不满意，可以回退到之前的任意状态
- **业务逻辑**：

  ```
  用户触发回退
    → 显示版本历史列表（时间线 + 版本摘要）
    → 用户选择目标版本
    → 预览目标版本内容（不覆盖当前）
    → 用户确认
      ├── 「覆盖」→ 用目标版本覆盖当前内容
      ├── 「合并」→ 目标版本作为新段落插入
      ├── 「另存为新章节」→ 创建新章节
      └── 「取消」→ 无事发生
  ```

- **依赖**：1.2
- **预估**：2 天

### 2.3 增量上下文更新（黑板增量 Merge）✅

- **描述**：用户手动修改章节后，黑板中的 `RecentChapters` 需要更新，但不是全量重建
- **业务逻辑**：

  ```
  用户保存章节
    → Orchestrator 收到通知
    → 定位到黑板中对应的 ChapterSection
    → 做增量更新（内容变更、字数变更、摘要重新生成）
    → 不触及其他分区（WorldSetting / Characters 不变）
    → 记录变更日志
    
  逆向：
    用户撤销保存
    → 回退到上一个黑板状态
    → 不触发 Agent，只恢复数据
  ```

- **依赖**：1.1, 1.3
- **预估**：2 天

## 阶段三：创作管理功能（P2） ✅ 已完成

这些是"创作管理"类功能，有业务逻辑但非核心体验。

### 3.1 卷管理 ✅

- **领域实体**：已有 `VolumeEntity`
- **描述**：作品分卷管理，支持卷的拆分、合并、排序
- **业务逻辑**：

  ```
  正向：
    新建卷 → 默认序号末尾
    章节移入/移出卷 → 更新 Chapter.VolumeId
    合并两卷 → 章节合并排序，删除目标卷
    
  逆向：
    恢复已删除卷 → 取出被删除章节，重新归组
    取消合并 → 还原合并前的状态
  ```

- **预估**：1.5 天

### 3.2 伏笔追踪

- **领域实体**：已有 `ForeshadowingEntity`
- **描述**：管理伏笔的埋设、追踪和回收
- **业务逻辑**：

  ```
  正向：
    设置伏笔 → 关联埋设章节
    伏笔回收 → 关联回收章节，状态改为 resolved
    AuditAgent 自动检测 → 标记"待回收"伏笔
    
  逆向：
    取消回收 → 状态改回 pending
    修改伏笔关联 → 更新埋设/回收章节
  ```

- **预估**：1.5 天

### 3.3 时间线管理 ✅

- **领域实体**：已有 `TimelineEventEntity`
- **描述**：管理故事内事件的时间线
- **业务逻辑**：

  ```
  正向：
    添加事件 → 指定时间和关联章节
    批量导入 → 从章节内容提取事件
    
  逆向：
    事件时间调整 → 影响前后事件的顺序
    删除事件 → 检查是否有其他事件依赖它
  ```

- **预估**：1.5 天
